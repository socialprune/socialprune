# ADR-011: Internationalization with React Intl and checked catalogs

- **Status:** Proposed
- **Date:** 2026-10-06
- **Hard constraints touched:** 2 (no catalog fetch), 5 (forbidden words are checked in both languages)
- **Related:** [ADR-002](ADR-002-dependency-licenses.md), [ADR-022](ADR-022-export-guide-content.md), [design specification](../../design/README.md)

## Context

The UI ships in German and English from 0.1 on. Messages need plurals ("1 entry", "4,000 entries"), selects (decision states), numbers and dates in the reader's locale, and they must be bundled: the page policy has `connect-src 'none'`, so catalogs cannot be fetched. The maintainer tests in German; the launch audience reads English.

Three stacks were built with Vite 8.3.3, React 19.3.0 and TypeScript 7 on 2026-10-06, each rendering an EN/DE heading, a plural, a decision-state select, `1.234,5` and `6. Oktober 2026` in `Europe/Berlin`, under the strict policy:

| Stack | Total app JS, gzip -9 | Over 67,819 B baseline | Locale-switch requests | Violations |
|---|---:|---:|---:|---:|
| Paraglide JS 2.26.0 | 69,293 B | 1,474 B | 0 | 0 |
| React Intl 12.1.4 | 82,178 B | 14,359 B | 0 | 0 |
| i18next 26.4.2, react-i18next 17.0.16, ICU plugin 2.5.0 | 95,268 B | 27,449 B | 0 | 0 |

TypeScript rejected unknown message IDs in all three. Only Paraglide also rejected a missing plural argument; React Intl and i18next do not infer argument types from imported JSON.

Paraglide's message-format plugin pulls `@inlang/sdk` 3.1.0, then `@lix-js/sdk` 0.19.0, then three `@bytecodealliance/jco-*` packages licensed `Apache-2.0 WITH LLVM-exception`. Under [ADR-002](ADR-002-dependency-licenses.md) that license needs its own exception record naming why no allowlisted option fits. React Intl fits, so no exception is written. i18next's extraction CLI 1.74.8 carries BlueOak-1.0.0 packages in its default graph.

## Decision Drivers

- Plural, select, number and date formatting through the browser's `Intl`, bundled.
- Unknown IDs and mismatched arguments caught before merge.
- Every package on the license allowlist.
- A contributor can add a language without learning a compiler.

## Options

### Option 1: React Intl 12.1.4 with bundled ICU JSON

**Pros:**
- BSD-3-Clause with an all-MIT/BSD transitive graph; one runtime package; no build plugin.
- ICU MessageFormat is a widely known syntax for translators.

**Cons:**
- 12,885 B more gzip than Paraglide in the trial.
- Argument types are not inferred; the project needs its own check.

**Effort:** not measured
**Risk:** Low.

### Option 2: Paraglide JS 2

**Pros:**
- Smallest bundle; per-message tree shaking; typed arguments.
- Generated functions catch a missing argument at compile time.

**Cons:**
- The message-format plugin graph is outside the allowlist, so it needs an exception that ADR-002 does not justify while an allowlisted option exists.
- `setLocale` without reload did not re-render React in the trial; its default locale switch navigates, which could drop unsaved review state.

**Effort:** not measured
**Risk:** Medium.

### Option 3: i18next with react-i18next and the ICU plugin

**Pros:**
- Large contributor familiarity.
- Mature ecosystem.

**Cons:**
- The largest bundle of the three, 13,090 B gzip above React Intl.
- Its extraction CLI's default graph is outside the allowlist.

**Effort:** not measured
**Risk:** Low.

## Decision

We chose **Option 1: React Intl 12.1.4 with bundled ICU JSON catalogs**, because it is the smallest stack that passes the license policy without an exception and needs no build plugin.

### Catalogs and types

- `apps/web/src/i18n/en.json` and `de.json`: flat objects of `"area.name": "ICU message"`. English is the source catalog. Both are imported statically and bundled.
- `apps/web/src/i18n/messages.d.ts` is generated by `pnpm i18n:generate` from `en.json`. It augments `FormatjsIntl.Message` with the union of IDs, and declares a map from each ID to its argument names and types, derived by parsing the ICU message with `@formatjs/icu-messageformat-parser` 3.5.21 (MIT). A typed `t(id, values)` helper on top of `useIntl().formatMessage` uses that map, so a missing or misspelled argument fails `tsc`.
- Message IDs are string literals at the call site. Dynamic IDs are allowed only from a typed `as const` table, such as decision values to message IDs.

### Checks in CI: `pnpm i18n:check`

1. `messages.d.ts` matches a fresh generation (drift check, like the schema check).
2. Every locale has exactly the keys of `en.json`, no more and no fewer.
3. Every message parses as ICU, and each locale's message has the same argument names and types as English.
4. Every `plural` has an `other` branch; English and German also need `one`.
5. Every ID used in `apps/web/src` (found with the TypeScript compiler API already installed as the `typescript` alias) exists, and every catalog ID is used.
6. The catalogs pass the forbidden-word check below.

### Forbidden-word check: `pnpm copy:check`

A separate script, `tools/copy-check/`, runs in CI on every pull request. The word list and the allowlist live in one file there, `words.ts`, and the [design specification](../../design/README.md#forbidden-words) points to it.

- **Scope.** The web catalogs (`apps/web/src/i18n/*.json`); CLI human messages and the fixed error-message table in `apps/cli/src/`; the guide data in `packages/core/src/guide/`, including the text of the generated `.ics` reminder; `skills/socialprune/**`; `README.md` and every Markdown file under `docs/` except the exemptions.
- **Exemptions**, because they quote the list: `AGENTS.md`, `.kilo/**` (which holds the writing rule), the section "Forbidden words" in `docs/design/README.md`, `tools/copy-check/**`, and the check's own test fixtures. Every other file in scope is checked.
- **Code is not prose.** In Markdown files, inline code spans, fenced code blocks and link targets (the URL inside the parentheses) are skipped, because they name identifiers such as the CSP keyword `'unsafe-inline'` or the action `actions/upload-pages-artifact`. Link text is checked. Catalogs, CLI messages and guide data have no such exemption.
- **English patterns**, whole words, case-insensitive: `safe`, `safely`, `safer`, `safest`, `safety`; `undetectable`; `bypass`, `bypasses`, `bypassed`, `bypassing`; `guarantee`, `guarantees`, `guaranteed`, `guaranteeing`; `deletes everything`; `upload`, `uploads`, `uploaded`, `uploading`.
- **German patterns**, whole words, case-insensitive: the adjective and adverb forms `sicher`, `sichere`, `sicheren`, `sicherer`, `sicheres`, `sicherem`; `Sicherheit` and every word starting with it (`Sicherheiten`, `Sicherheitsfunktion`, `Sicherheitskopie`); `garantiert`, `garantieren`, `Garantie`, `Garantien`; every word starting with `unentdeckbar`; every word starting with `umgeh` in the sense of getting around a rule (`umgehen`, `umgeht`, `Umgehung`) and the participle `umgangen`; `löscht alles`; `hochladen`, `hochgeladen`, `lädt hoch`.
- **Allowlist.** The backup vocabulary stays allowed: `sichern`, `sicherst`, `sichert`, `gesichert`, `Sicherung`, `Sicherungen`, `Sicherungskopie`, `Sicherungskopien`. The allowlist matches whole words only, so `sichere` (an adjective form) is still caught even though `sichern` is allowed. `Sicherheitskopie` and `Sicherheitskopien` are not allowlisted, because the copy says `Backup`; they would join the allowlist only if a catalog started using them. `Official` and `offiziell` pass only inside `official data export`, `official export`, `offizieller Datenexport` and `offiziellen Export`.
- **Tests in both directions.** A fixture file lists each forbidden form in a short sentence and the check must report every one; it includes `Für deine Sicherheit`, which must fail. A second fixture uses every allowlisted word and every exempt CSP keyword and the check must report none.

### Locale choice

- First visit: the first entry of `navigator.languages` starting with `de` selects German; otherwise English.
- A language switch in the header and in Settings. The choice is stored in `localStorage` under `sp-locale`, read synchronously before the first render, and sets `<html lang>`. Switching re-renders in place; no reload, no lost state.
- Dates use the workspace time zone ([ADR-012](ADR-012-time-zone-grouping.md)); numbers use the UI locale.
- The CLI prints human-readable text in English in Phase 2. `socialprune guide <platform>` takes `--lang de|en`, because its content comes from the shared guide data in [ADR-022](ADR-022-export-guide-content.md), not from the web catalogs.

### Adding a language

1. Copy `en.json` to `<code>.json` and translate every value.
2. Add the code to `SUPPORTED_LOCALES` in `apps/web/src/i18n/index.ts` and to the guide data.
3. Run `pnpm i18n:check` and the browser tests with that locale; they include a pseudo-locale run (`en-XA`, generated in tests only) that lengthens every string by 40 percent to catch clipped layouts.
4. A native speaker reviews the pull request. A language ships only when every key is present.

## Consequences

### Positive
- One runtime dependency and one development dependency, both on the allowlist; no build plugin to maintain.
- Arguments are type-checked through the generated map, closing the gap the trial found.

### Negative
- About 14 KB gzip over a no-i18n baseline, and both catalogs ship to every visitor.
- The check script is project code that needs its own tests.

### Risks
- **The generated types drift from the catalog.** Mitigation: rule 1 fails CI on drift.
- **German strings overflow compact controls.** Mitigation: the pseudo-locale run and German layout tests at 320 px width.
