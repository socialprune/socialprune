# Gate G1: evidence

Gate G1 closes Phase 1. It has four conditions. Each section below names the proof, the command that reruns it, and what it does not cover. Everything was observed on 2026-10-06 against commit `feb6748` on Windows 11 with Node 24.14.1 and Chromium 153.0.8010.12 (Playwright 1.63.0). CI runs the same tests on Ubuntu for every push.

An independent review of an earlier version of this file, against `ad22ff3`, returned a revision with two blocking findings: `structure` leaked handles when it was pointed at a folder that holds more than one export (section 4), and the abort browser test raced against fast imports (section 2). The race also failed CI once, on `6f5e0a1`. Both are fixed. The same reviewer rechecked both at `feb6748`, reran `pnpm test` (246 tests), `pnpm test:e2e` (53 tests) and the abort test 20 times, all with exit code 0, and accepted the gate with findings that change only the wording of the residual in section 4.

## 1. Every format variant in the test data is read

The synthetic fixtures hold 22 X variants and 30 Instagram variants under `fixtures/synthetic/`. Each variant carries an `expected.json` that the generator computes from the data it writes, never from the parser.

- `pnpm test` imports every variant twice, once as a folder and once as an in-memory ZIP, and compares status, records, diagnostics and every item with `expected.json` (`packages/adapter-x/src/index.test.ts`, `packages/adapter-instagram/src/index.test.ts`). Instagram variants are imported a second time to prove the item ids are stable.
- `pnpm test:e2e` imports the 50 variants whose expected status is not `unknown-format` (21 X, 29 Instagram) through the built page and its module worker and compares records, diagnostics, export dates and item ids (`apps/web/e2e/import.spec.ts`). A separate test fails if either platform has no variants, so the sweep cannot pass empty.
- `pnpm fixtures:check` regenerates all 52 variants and found 0 changed files.

Observed in a clean worktree at `feb6748`: 246 unit tests and 53 browser tests passed, each command with exit code 0.

Not covered: the formats are reconstructed from public descriptions and other parsers, not from a real export. Each variant description marks its assumptions. Spike S4 checks them against the maintainer's own exports.

## 2. The 100,000-item archive goes through the browser without a crash, with time and memory recorded

`pnpm measure:g1` generates a seeded X archive with 100,000 tweets (6,236,036 bytes as ZIP, 103,004,960 bytes uncompressed) and imports it in headless Chromium through the real page and worker. The page keeps every item batch in an array, as the review UI will. Memory is the sum over all Chromium processes that CDP reports, page and worker included, sampled from the operating system every 145 to 166 ms on average.

Run on `feb6748`, finished at 19:00 UTC:

| Run | Items | Wall time | Peak private memory | Peak working set |
|---|---:|---:|---:|---:|
| M1 run 1 | 100,000 | 8.15 s | 403.00 MiB | 482.62 MiB |
| M1 run 2 | 100,000 | 8.72 s | 389.80 MiB | 483.80 MiB |
| M1 run 3 | 100,000 | 7.61 s | 405.66 MiB | 497.43 MiB |
| M2, ZIP64 archive of 4,703,857,916 bytes | 100,000 | 7.91 s | 417.72 MiB | 619.25 MiB |
| M3, abort halfway | 52,000 received, then discarded | 30.1 ms from abort to the worker's acknowledgement | 293.15 MiB | 511.33 MiB |

M2 adds five stored padding entries so the archive passes 4 GiB. Its header check confirms ZIP64 offsets beyond that limit, and the recorded reads never touched the padding. The run hashes the executable source before and after and binds the numbers to it (`8e92e61a…07df7`). The method, the sampling gaps, an earlier run on `ad22ff3` and the machine readback are in `docs/spikes/S1.md`.

These numbers are measurements on one desktop, not promises. Sampling can miss peaks shorter than about 300 ms, and memory after abort stayed above the baseline because no garbage collection was forced. The same import in a separate Node process took 6.90 s on `ad22ff3` and 16.45 s on `feb6748`, although the import code did not change in between, so single Node timings on this machine vary more than the browser rows.

The abort browser test now fires Abort from the first item batch inside the page (`abd6bfb`). After that fix the full browser suite passed, and the abort test alone passed 30 of 30 repeats in the web lane and 20 of 20 in a clean worktree.

## 3. No archive content is executed

Archive files are data. Core splits a top-level JSON array by scanning brackets and string state and calls `JSON.parse` per element (`packages/core/src/json/`). A `.js` export file is accepted only with one strict `name.path = ` prefix in front of the array or object, and only whitespace and an optional `;` after it.

- The X variant `injection` puts `(function(){globalThis.__pwned = 1})() || [...]` in front of valid-looking tweets. The adapter test expects status `partial` and checks that `globalThis.__pwned` stays undefined. The browser test imports the same fixture and, after the import is complete, checks `__pwned` in the page and in the worker that parsed the file.
- Core tests reject trailing code after the array, two assignments and a top-level object where an array is required, and check `__pwned` there too.
- ESLint forbids `eval`, `new Function`, implied eval and `javascript:` URLs in `apps/`, `packages/` and `tools/` (`eslint.config.js`; spikes and fixtures are excluded).
- The page's meta CSP allows neither `'unsafe-eval'` nor `'wasm-unsafe-eval'` nor inline scripts, and the browser tests record no CSP violation during normal imports.

Not covered: the worker's own CSP. GitHub Pages cannot send response headers, so the worker policy comes later through the service worker, as spike S3 worked out (`docs/spikes/S3.md`).

## 4. `structure` returns only keys and types

`socialprune structure <path...> [--json]` reports file patterns, assignment targets and key paths with their JSON types, never values.

- Paths: digit runs become `N`. Every folder above an export's data directory (`data`, `your_instagram_activity`, `account_information` and the others in `KNOWN_EXPORT_DATA_DIRECTORIES`) becomes `<root>`, and so does any folder named like an export (`instagram-<handle>-<date>-<token>`, `twitter-<date>-<token>`). When no known directory occurs, the top folder becomes `<root>`.
- Keys: a key that is all digits, holds five or more digits in a row, contains `@`, starts with `http` or is longer than 64 characters becomes `<key>`, and so does a key or folder that contains a handle taken from the archive or folder names. In every other key, digit runs become `N`. An object with more than 50 distinct keys collapses to `<key>`.
- Messages, chats, follower and following lists and login, IP, device, contact and security files are counted and never opened (`PRIVATE_PATH_PATTERNS`).
- The CLI prints no paths of its own, and it asks people on stderr to check a report before they share it. Run it as `pnpm -s socialprune structure ...`, because without `-s` pnpm prints the command line with the path.

Proof (`packages/core/src/structure/structure.test.ts`, `apps/cli/src/cli.test.ts`):

- Unit tests plant distinctive values, a username, an email-like string, a digit id used as value and as key, and a handle as a key, and assert that none of them appears in the serialized report. They cover an export folder with a sibling file, an export one level down in a `Downloads` folder, two exports side by side, and a followers map whose keys are planted handles. Private files are served by a reader that throws if opened.
- A sweep takes its forbidden values from fixture metadata, never from the code: every account handle and account key in `expected.json`, and the handle and token of every archive name that follows the real naming pattern. It runs on three input shapes: each export folder alone, where it also checks that no leaf value of the export's `.json` and `.js` files appears; each fixture folder with its `variant.json` and `expected.json` beside the export; and each whole platform folder as a parent of many exports. Every variant with data must contribute checked values, and `instagram/empty-comments` is the one variant without scalars and is counted by name.
- A second sweep takes the first directory of every data file from the fixtures and requires it to be a known export directory, so folders above it collapse.
- Before the fix was accepted, the implementing lane ran the new tests against the `structure` implementation from `ad22ff3` and they failed 9 times, so they detect the leak they were written for. The read-only review did not repeat this run.
- `apps/cli/src/cli.test.ts` runs the real CLI on a synthetic ZIP, checks that a planted value is absent from stdout, and checks the notice on stderr and in `--help`, but not in `--json` output.

Observed in a clean worktree at `feb6748`: `pnpm -s socialprune structure` over `fixtures/synthetic/instagram`, `fixtures/synthetic/x` and `fixtures/synthetic/instagram/two-accounts` exited 0, and none of the fixture handles or archive tokens appeared.

Not covered, and visible as names in a report:

- someone else's username used as an ordinary key in an unknown, non-private file with at most 50 keys;
- folder names below the top folder when a file's own path contains no known export directory;
- an export folder or ZIP whose name departs from the exact export pattern, for example a browser's ` (1)` suffix or a renamed folder. It is not recognised as an export name, so the user's own handle is not masked in keys, and the folder name stays visible under the condition above. The review showed this with `instagram-rev_handle-2026-01-02-zz9q (1)`, which printed `rev_handle` as a key.

`docs/BACKLOG.md` BL-004 tracks these. The ` (1)` case gets its code fix before spike S4 runs, because S4 is the first time a report from a real export leaves the maintainer's machine.
