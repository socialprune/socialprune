## Rubric v2 and the local labelling page

The corpus loader combines the unchanged original 400 JSONL entries with 160 hand-authored entries under `fixtures/synthetic/classify/additions-v2.mjs`, IDs `s2-401` through `s2-560`. All additions are ordinary posts and comments about invented people, places and groups. Fiction provenance stays in the file comments and metadata, not in the text: a fiction frame could cue a model to discount a hostile statement. The loader rejects new texts containing `erfunden`, `fiktiv`, `fictional`, `invented` or `made-up`. Reporting, condemnation, quotes used to criticise, reclaimed self-description, explicit friendly irony, neutral origin or gender mentions and political criticism without group hostility are present as near misses. Harsh slurs are omitted as `[Schimpfwort]` or `[slur]`, so the test cannot measure recognition of those words. The additions appear in a fixed mixed reading pass before the page permits rubric acceptance or labelling. The maintainer can therefore read exactly these 160 first, without seeing their coverage notes.

Read each addition, accept the rubric, label all entries, then confirm the separate finalization button. Since no maintainer labels exist, this binding changes before his first labelling pass. **Time is not measured.** A planning allowance of 25 to 50 seconds per labelled entry gives roughly 4 to 8 hours for 560, plus roughly 30 to 60 minutes to read the 160 additions first. Pauses, multiple labels and rubric revisions may take longer. Resume means this need not happen in one sitting.

## Label by hand first

Read [the rubric draft](../../fixtures/synthetic/classify/RUBRIC.md), change it if needed, and retain its category and risk table rows. Then run from the repository root:

```powershell
node spikes/s2-classify/label.mjs
```

The tool asks for `ja` to record rubric acceptance. It shows platform, kind, UTC date, engagement, references and text for one item at a time. Category keys are `1` through `9`, with `0` for `unclear`; risk is `0` through `3`. A note is optional. `u` undoes the most recent current label, and `q` saves progress and exits. Running the same command resumes.

The append-only `labels.history.jsonl` records acceptance, labels and undo events. Undo never rewrites earlier events. After all 400 items have current labels, run this separate command and confirm `ja`:

```powershell
node spikes/s2-classify/label.mjs --finalize
```

It exclusively creates `labels.jsonl` once, with exactly one `{ itemId, category, risk, note, labeledAt, labeler: 'maintainer' }` row per item. `labels.manifest.json` records the accepted rubric hash, item hash, label hash and finalization time without altering the label-row shape. Finalization refuses partial coverage or an existing final file. Item or rubric changes block resume; stale hashes, duplicates, unknown IDs, invalid values and future finalization times block evaluation. A partial finalization also blocks evaluation rather than pretending the file is complete.

All three files are maintainer-authored and are absent from the repository at the end of this session. The harness reads the final labels and manifest, never the history or coverage metadata. Tests drove scripted stdin against smoke-derived copies under the S2 temp directory, not the real labels path.

### Shared output contract

The generative tiers receive the same data-not-instructions contract, current rubric, serialized item and exact assessment metadata. Every output is checked with the linked core `AssessmentSchema` and the ten `DEFAULT_CATEGORIES`. Invalid JSON, malformed reasons, mismatched metadata and other invalid fields produce a counted `unclear` assessment with risk 1. Evidence outside the item text is removed and counted independently, including when another field is invalid. Only an empty Qwen thought wrapper is accepted as transport syntax; nonempty reasoning or markdown outside JSON is invalid.

The transport JSON schemas omit regex/date-format constraints unsupported by the grammar engines; the real core validator still enforces them after inference. Ollama initially rejected its grammar, and WebLLM required an explicit schema string for its JSON grammar. Those integration attempts remain in ignored results, not the accepted smoke record.

Rules and NLI do not execute natural-language instructions. Rules use short original German/English patterns for contact details, abuse, politics, adult innuendo and party/drug terms, plus empty-content detection and limited combined date/engagement/style signals. They are an uncalibrated baseline, not `packages/classify`. NLI receives the current rubric's category definitions as hypotheses over item text, then four separate risk hypotheses; the adapter emits the same validated JSON shape. It has no generated rationale or extracted evidence, so its reason describes its selection and evidence is null. This is not equivalent to a generative model following the complete rubric or using all metadata, and its confidence is an NLI score, not a calibrated probability.

Ollama rejects names containing `cloud`, `/api/show` remote identity and remote `FROM` URLs. It requires a local GGUF record, records the model digest and exact answering name, and rejects mismatched answers. The service being on localhost alone is not the local-compute check. Models remain warm within a run and receive an explicit unload request at close; `/api/ps` was empty after the final trial.

## Limits and next action

The corpus is invented, equally bilingual and deliberately includes overlapping edge cases. It is not a sample of platform prevalence. Generated labels marked `maintainer` would not satisfy this protocol; the file checks establish structure and snapshot binding, while the maintainer's own labelling establishes authorship. The harness cannot prove a human did not consult a model outside it.

Precision/recall, risk agreement and default-tier selection remain unmeasured. Prompt API inference, authenticated reference inference, other Ollama models, repeated performance trials and real-export classification were not attempted. There is no product classifier or product integration in this spike. Runtime transport outputs can be valid JSON while still being wrong, which is why smoke results do not choose a default.

The maintainer's next action is to accept or edit the rubric, run the German labeller without looking at design metadata, and finalize all 400 labels. Only then can S2 continue with the evaluation commands and category metrics. The reference tier also needs a model name and explicit key file from him.

Implementation and start-stage validation are separate from repository delivery. This lane made no commit, push or other Git mutation; integration owns delivery. Per LL-2026-10-001, external availability and machine sizes above carry their observation times rather than being treated as permanent machine facts.
