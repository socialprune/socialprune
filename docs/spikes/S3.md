# S3: Cached model inference under an offline CSP

## Question and answer

Can the app shell and a local model, cached during an earlier online visit, run analysis in a web worker without network access under `connect-src 'none'`?

Yes, for both tested runtimes with the cache-loading changes below. Transformers.js classified three invented sentences in a worker under V1 while Playwright had the browser context offline. WebLLM did the same with Qwen3 in headed Chromium. The verifier observed cached document and worker responses, checked their CSP headers, and found no fetch/XHR requests, external request origins or CSP violations in the successful cache-only rows. Stock library loading did not meet V1.

## App, worker and CSP

A hand-written service worker precaches the HTML pages, bundled scripts, worker and both self-hosted runtimes. This avoided a PWA plugin and let the spike attach a variant-specific CSP to cached worker responses as well as documents. Restricting only the document would not establish the worker's network policy. The preview middleware applies the same headers before service-worker control.

Each measured offline row calls `context.setOffline(true)`, reloads the app, opens the variant page and creates a new module worker. The verifier checks `fromServiceWorker()` for the reload, document and worker. The runner records `page.on('request')`, `requestfailed`, the corresponding context events including worker/SW traffic, response headers, request timings and sizes, and worker/document `securitypolicyviolation` events. It does not intercept requests or replace browser `fetch` in the test.

All variants used this policy, with the changes in the table:

```text
default-src 'none';
script-src 'self' 'wasm-unsafe-eval';
worker-src 'self';
connect-src 'none';
style-src 'self';
img-src 'none'; font-src 'none'; object-src 'none';
base-uri 'none'; form-action 'none'; frame-ancestors 'none'
```

| Variant | Difference |
|---|---|
| V1 | Policy above |
| V2 | `connect-src 'self'` |
| V3 | `connect-src 'self' https://huggingface.co https://cdn-lfs.huggingface.co https://cdn-lfs-us-1.huggingface.co https://cas-bridge.xethub.hf.co https://us.aws.cdn.hf.co` |
| V4 | V1 plus `blob:` in `script-src` |
| V5 | V1 without `'wasm-unsafe-eval'` |

V3 includes known CDN candidates for acquisition, but only Hugging Face and `us.aws.cdn.hf.co` were contacted here. Their redirect origins must be remeasured if the download route changes. No variant permitted JavaScript string evaluation or inline scripts.

### Cache changes in our code

**Transformers.js, `cache-bytes`.** `env.useBrowserCache = true` already loads model bodies from CacheStorage. However, 4.3.0's `pipeline()` performs metadata probes at `resolve/main/tokenizer_config.json` even with a pinned model revision. The spike sets `env.fetch` to read the pinned cached response first. It permits a real download only on the acquisition page V3 while online; other cache misses throw. This is app cache-loading code, not a Playwright request stub. Separately, the spike sets `env.useWasmCache = false`, reads the self-hosted WASM with `caches.match`, assigns its ArrayBuffer to `env.backends.onnx.wasm.wasmBinary`, and imports the self-hosted `.mjs` normally. This avoids the stock cache loader's blob factory.

**WebLLM, `cache-lib`.** `appConfig.cacheBackend = 'cache'` reads cached config, tokenizer and weights directly. A relative `model_lib` still calls `fetch`, so V1 blocks it before the service worker can return the cached WASM. Our code copies that response with `caches.match` into WebLLM's `webllm/wasm` cache and supplies the absolute same-origin library URL. On `127.0.0.1`, WebLLM then uses its artifact cache instead of `fetch`. Its source explicitly fetches library URLs containing `localhost`, so that spelling cannot be substituted without another check. No library patch, blob URL or IndexedDB conversion was needed.

### Direct browser-cache probe

On the offline V1 page, `fetch('/ort/ort-wasm-simd-threaded.asyncify.wasm')` failed with `TypeError: Failed to fetch` and a document `connect-src` violation. The service worker's fetch-event counter for that URL stayed at 1 before and after the call. `caches.match` then returned all 26,861,777 bytes from the same URL. This directly observed the blocked-fetch-before-SW behavior and successful Cache API read in the tested browser.

## Minimal tested offline CSP and recommendation

Both app-owned loading paths worked with V1 as printed above. They needed no `blob:` in `script-src` or `worker-src`, no remote `connect-src` origin, and no cross-origin-isolation headers in this one-thread trial. Dropping the WASM compilation permission failed both. The stock WebLLM path worked with V2; stock Transformers.js had no working offline variant because its metadata probe remained uncached. Allowing `blob:` solved the factory import only after our metadata cache change. Ancillary directives such as `style-src` were not individually minimized.

For SocialPrune, use a separate acquisition page with a measured Hugging Face/CDN allowlist, then reload into an analysis document and worker with `connect-src 'none'`, `script-src 'self' 'wasm-unsafe-eval'` and `worker-src 'self'`. Self-host the JS and WASM, pin model revisions, and make cache misses explicit rather than downloading during analysis. Transformers.js's WASM-byte and metadata path and WebLLM's absolute artifact-cache path both support that design here. This is a recommendation inferred from the trial, not validation of a shipped PWA. The product's service-worker policy also needs its own check because it is a separate execution context.

## Limits

This tested one desktop, one Chromium build, two models, CacheStorage, a warm online cache and a localhost origin. It did not test Firefox, Safari, phones, IndexedDB/OPFS backends, multiple WASM threads, browser restarts while offline, storage eviction, quota exhaustion, corrupted or partial downloads, real export parsing, classification quality, a GitHub Pages base path, or a production service-worker update strategy. The initial trials were used to repair integration; the final matrix used two fresh disposable profiles and matching source hashes. A reused-profile development run briefly loaded an older service worker and is not final proof.

Offline mode was Playwright's context setting, not an unplugged cable or packet capture. App/worker events do not prove that the browser process itself makes no background connections. V1 also restricts only the measured document and inference worker, not every possible future app execution context. The CSP changes used localhost response headers plus service-worker response headers; GitHub Pages cannot be assumed to reproduce that header setup. A deployment-specific check must prove document and worker policies there.
