# S4: Compare parser formats with scoped exports

## Question

Which X and Instagram export shapes differ from the synthetic fixtures, and what do those differences change in parser detection, imported counts and diagnostics?

The harness is under `spikes/s4-real-exports/`, outside the workspace and CI. It has no dependencies of its own and runs as TypeScript source with Node 24 type stripping. It imports the repository's core and adapters by relative path; the existing root dependencies must already be available. No installation is needed for this spike.

## Method

`check.ts` opens the supplied ZIPs or folders together with `openArchivePaths` and calls `importArchive` with both real adapters. Its item callback counts batches and retains no items. The core importer still keeps its duplicate-detection signatures, and the X adapter can retain its note index. The harness does not extract ZIP entries, write files, run archive code, contact a model or send network requests.

A reader wrapper records the entries each adapter actually opens during detection and parsing. A private-category read attempt makes the harness fail, even if an adapter catches the underlying error. `describeStructure` receives only those recorded entries. Files neither adapter opened contribute normalized filename patterns and counts only; their contents and JSON keys are not read. Private entries contribute only a skipped count.

Each parser-read tweet or JSON comment file also has a `rowFiles` entry with a positional `file-1` label and normalized pattern. The harness streams that file again with core's `parseJsonArrayStream`; Instagram framing admits a top-level array or one object property containing an array. `rowsSeen` counts complete parsed elements. `rowsRejected` counts elements for which the adapter's exported row function returns null, using `parseComment`, `parseLegacyComment` or X's `tweetItem` by relative import. It does not count duplicates, conflicts or failures during later item validation. X note rows have no exported row parser, so their `rowParser` is `seen-only`, `rowsRejected` is null and `rejectedShapes` is empty. Deleted-tweet rows can be counted and checked even though they do not become imported items.

`streamError` is true when that streaming read or JSON framing fails. Counts then describe only the complete elements before the failure, not an estimate of unread rows. An exception message never reaches the report. `rejectedShapes` retains up to ten distinct signatures, each with a count; a signature is the sorted set of normalized row key paths and their types, with no values. The first ten distinct projected signatures are retained, later matching rows increase their counts, and additional distinct signatures are omitted. `rowsRejected` still counts every null result, so the retained shape counts need not add up to the total. Shape limits or unexpected row-parser exceptions fail the whole report rather than conceal a report-construction failure as a stream error.

The synthetic reference is the union of parser-read structures from every archive folder listed in each variant's metadata under `fixtures/synthetic/x/` and `fixtures/synthetic/instagram/`. It is recomputed by running the same real adapters and `describeStructure`, not inferred from expected items. Differences compare the normalized pattern, key path and observed value type. `onlyInInput` can therefore identify a new path or a new type at an existing path. `onlyInFixtures` describes fields or types in the synthetic union that the input did not show; it is not a list of mandatory export fields.

## Privacy design

The output is one JSON object with these top-level fields:

| Field | Content |
|---|---|
| `inputs` | Positional labels, ZIP/folder, size class, entry count, rejected count and private entries skipped |
| `adapters` | Platform, detection result and known variant or null |
| `import` | Status and per-platform record counters, item kinds, media/unknown engagement, duplicates/conflicts and stripped diagnostics |
| `structure.parserRead` | Platform, normalized patterns, key paths/types, per-file row counters/rejected shapes and synthetic differences |
| `structure.otherFiles` | Normalized patterns and counts only |
| `performance` | Import milliseconds and observed process peak RSS bytes |

Sizes use decimal boundaries of 10 MB, 100 MB, 1 GB and 4 GB. Folder size classes use the sum of accepted entry sizes; ZIP classes use the ZIP's disk size. RSS includes the process's synthetic-reference preparation and is not an isolated memory delta for the import. Import timing excludes reference preparation and the later structure comparison.

`schema.ts` is a strict hand-written validator. It lists every field, checks exact object keys and array shapes, admits only finite nonnegative integer counters and known enum values, and verifies account and item-kind totals. It rejects unknown variant strings rather than printing an unexpected adapter value. Unknown diagnostic categories become the fixed token `other`.

Patterns retain only fixed structural directory names. Export wrappers collapse to `<root>`, unknown directory segments to `<segment>`, and unknown basenames/extensions to fixed tokens. Known basenames use tags such as `data/<tweets>.js`, never a literal entry path. Key paths tag known schema keys, for example `$[].<tweet>.<full_text>`. Unknown keys collapse to `<key>`, including unexpected keys inside a file an adapter read. Two fixed aliases avoid echoing the synthetic archive identity `archive`: `archiveInfo` becomes `<exportInfo>` and `isArchivePartial` becomes `<isPartial>`.

New key vocabulary has public source comments beside each group in `schema.ts`. The Instagram names come from a documented format snapshot and a public description of downloaded JSON; X edit and manifest names come from pinned MIT parser type definitions, and the sensitivity field from a public description of a `tweets.js` row. Only field names are admitted, not the sources' example values or code.

The report omits item text, IDs, account keys, handles, dates, archive/folder names, assignment targets, filenames outside normalized patterns, diagnostic messages and detection reasons. Before stdout receives any byte, the report and its serialized JSON both pass the validator. Failure produces no JSON and exit 1. Stderr contains only `S4_USAGE`, `S4_CHECK_FAILED` or `S4_REPORT_INVALID`, never an exception message or path.

## Synthetic proof and rerun

Run from the repository root:

```powershell
node --test --test-concurrency=1 spikes/s4-real-exports/test/harness.test.ts spikes/s4-real-exports/test/rows.test.ts
pnpm exec tsc --noEmit -p spikes/s4-real-exports
```

Tests run every X and Instagram fixture as its export folder or folders and again as ZIPs created in an owned temporary directory. They compare import status, variants, account counts, item-kind/media/engagement counts and diagnostics with `expected.json`. Per LL-2026-10-002, forbidden values come from the input data and expected account metadata, not the report's normalizer. The checks reject every fixture handle/account key, export name and token, and string or numeric leaf value at least four characters long, case-insensitively. Malformed and injection fixtures are inspected lexically as data, never executed.

An adversarial synthetic ZIP covers a duplicate download suffix, unexpected username/email keys, a messages folder and a copy nested two levels down. A test-only filesystem observer proves the nested unrecognized export is inventoried without reading its contents. A deliberately broken report retaining an archive name must fail the privacy oracle and validator; the output test asserts empty stdout. Additional mutations exercise unrecognized labels, variants, categories, patterns, paths, counters and serialization hooks. The real CLI is tested for one report on success and symbolic stderr on failure.

The original fixture/privacy tests remain unchanged. Additional hand-built rows cover missing comment text with an extra array, a malformed field, legacy tuples, wrapped arrays with trailing syntax failures, and an injected stream failure after a complete row. Expected rejected shapes are written by hand, not produced by the normalizer. Rejected text, handles, URLs and raw unknown keys must not escape; a negative control puts an unapproved raw key in a shape and expects validation failure with empty stdout.

The standalone package has no dependency entries. A test compares the root `package.json`, `pnpm-workspace.yaml` and `pnpm-lock.yaml` byte-for-byte before and after the suite. The suite removes only its own synthetic temporary directory. Re-run these checks after any core, adapter or report change before using the harness on a scoped copy.

After explicit maintainer scope and repository delivery, the parent alone runs:

```powershell
node spikes/s4-real-exports/check.ts "<scoped-X-copy.zip-or-folder>" "<scoped-Instagram-copy.zip-or-folder>"
```

The parent reads only the report. This document and the synthetic proof do not authorize any other lane to read, list, search, copy or parse a real export. Any format deviation must be reproduced with invented data before it reaches tracked source or fixtures.
