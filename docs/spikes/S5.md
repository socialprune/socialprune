# S5: Instagram's comments view, read only

## Question and answer

Can SocialPrune find each of the person's exported Instagram comments in Instagram's own "Your activity > Comments" view, open the post it belongs to, and prove that the comment there is the exported one, without changing anything ([ADR-028](../architecture/adrs/ADR-028-instagram-signed-in-session.md), spike S5)?

Yes, through the post page. The list alone does not carry enough: its rows hold no link and only a relative age. One click on a row opens the post, and there the comment sits under the person's username with its exact time. In a sample of 20 rows whose text equals exactly one exported comment, the text appeared under the person's username on all 20 posts. On 18 of them the comment's time matched the export within a minute and the post belonged to the exported post owner. The other 2 had a different time and a different post owner, so they were other comments that happen to share a text with an exported one. A match by text alone would have linked them wrongly. The time check on the post rejected them.

## Trial identity

The maintainer ran it on his own account on 2026-10-14 and 2026-10-15 UTC, under his written scope in the conversation: first read only with scrolling (card IG-1), then widened to sorting, opening posts and expanding a post's comments (card IG-2, option B). He signed in by hand in a plain Edge window with no program attached, in a dedicated profile folder outside the repository. The probes were local scripts outside the repository, run by the parent session only. Instagram's page language was English.

## Method

Each probe launched the dedicated profile with Playwright and the installed Edge, with the Chromium sandbox on and the automation banner visible. Requests to hosts outside Instagram and its CDNs were aborted. A request whose `x-fb-friendly-name` named a state change (delete, like, follow, comment and similar) would have been aborted and counted. None occurred in any probe. The probes clicked only these controls: "Sort & filter", "Oldest to newest", "Apply", a comment row to open its post, and "Load more comments" or "View replies" on a post. They never clicked Select, Delete, a like, a reply or a follow, never typed, and never ran a script in Instagram's page.

Rows were compared with the local export inside the probe process. Output was limited to counts, fixed class names and booleans, checked against an allowlist pattern and the export's handles before printing. No comment text, handle, link, post code or time left the probe.

## Results

| ADR-028 question | Observed |
|---|---|
| 1. Does each row show its post? | Not in the markup. A row is a `role="button"` element with the person's username, the comment text and a relative age, and no `href`. Clicking it opened the post at `/p/<code>/` for 20 of 20 rows. The post's code also appeared in the list's network answers for those 20 posts, but which row it belongs to there was not established. |
| 2. How far back, in what order? | The default order is newest first. In that order neither the mouse wheel nor the End key loaded more rows. The loading indicator stayed below the visible area, and the cause is not known. "Sort & filter" offers newest or oldest first and a start and end date. After "Oldest to newest" and Apply, the list began with the oldest comments, and scrolling over the rows loaded further batches. Reaching the very last row was not tried. |
| 3. What date does a row show? | A relative age in weeks, days or hours. On the post, the comment's own permalink (`/c/<id>/`) holds a `time` element with the exact time. |
| 4. Can a match be proven? | Text under the person's username: 20 of 20, 5 of them only after one click on "Load more comments" or "View replies". Exact time within 60 seconds and the exported post owner: 18 of 20. The remaining 2 were other comments with the same text. |
| 5. What do Select and Delete look like? | Not examined beyond the list's "Select" text. This needs its own scope. |
| 6. What does the page change in the profile? | At the first automated launch Edge removed its built-in extension folders and the file count fell slightly, as it did in the X profile. The session stayed signed in. No other change was observed. |

Going back from a post resets the list to newest first, so a run that walks older comments has to sort again after each post. Comments that are replies or sit lower in a long thread appear only after the post's own "Load more comments" or "View replies" control.

## What this changes

ADR-028 planned to match list rows to exported comments by text, date and post owner, and to delete from the list. The list has no exact date and no post owner, and text alone links some rows to the wrong comment. Confirming each candidate on its post, by the person's username, the exact time and the post owner where the export has one, closes that gap, and the post page is also where the context to keep is: the post's author, caption, time and image. Whether ADR-028 changes to "find in the list, confirm on the post" is the maintainer's decision. Deletion is not examined here.

## Not covered

- Select mode, the Delete control and its confirmation (question 5).
- The date filter, and whether the oldest-first list reaches every comment.
- Instagram's limits for reading many posts in a row.
- German or other UI languages. Every label above is English.
